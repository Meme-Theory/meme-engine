# Investigation Plan Template

The investigation pipeline (`sessions/investigation/`) is a parallel exploratory track that runs alongside the main session pipeline. This template is the investigation analog of `.claude/templates/plan-compute.md`; it shares that template's per-wave / consolidated / plan-index shapes and the same per-gate block structure. **Only three things differ** from a session plan:

1. **Seed provenance** -- an investigation plan is generated by `/rclab-plan --investigation` from a **free-form input** (an exploratory survey, a synthesis, any free-form document), NOT from a prior session's working-paper carry-forwards.
2. **Namespace** -- files live under `sessions/investigation/investigation-{n}/` and `{{COMPUTATION_DIR}}/investigation-{n}/` (see the path table), not `session-{N}`.
3. **Mixed gate types** -- a single investigation wave may carry `compute`, `review`, and `workshop` gates side by side. Each gate declares its `gate_type`; `/rclab-coordinate` juggles the three dispatch patterns directly.

(There is NO `solo` gate_type: a gate is always dispatched to a positioned specialist agent, never run inline by the orchestrator. The no-spawn mode is `/rclab-solo`, a SEPARATE session launched as a research agent, not a per-gate type.)

Everything else -- the gate-block structure, the pre-registration discipline for compute gates, the carry-forward compute-vs-non-compute split -- is identical to the session pipeline. Read `plan-compute.md` for the shared shape; this file documents only the deltas.

| Shape | One file per | When |
|:------|:-------------|:-----|
| Fanout (default) | wave -- `investigation-{n}-plan-w{i}.md` + thin `investigation-{n}-plan-index.md` | the default (per-wave files keep each wave independently dispatchable) |
| Consolidated | investigation -- `investigation-{n}-plan.md` | small efforts (few waves) |

## Namespace (path table)

```
sessions/investigation/index.md                          # the registry (rclab-plan registers; rclab-investigate housekeeps)
sessions/investigation/investigation-{n}/
  investigation-{n}-seed.md            # the free-form input digest (cites the source doc(s))
  investigation-{n}-partition.md       # wave partition manifest (theme + owner + gate_type per item)
  investigation-{n}-plan-index.md      # fanout index (consolidated: investigation-{n}-plan.md)
  investigation-{n}-plan-w{i}.md       # per-wave plan (MIXED gate types)
  investigation-{n}-w{i}-workingpaper.md   # per-wave working paper
  investigation-{n}-results-index.md   # thin index of per-wave working papers
  investigation-{n}-{short}-synthesis.md   # review-gate deliverables (/rclab-review pattern)
  workshops/{slug}.md                  # workshop-gate deliverables (/rclab-workshop pattern)
{{COMPUTATION_DIR}}/investigation-{n}/
  inv{n}_w{i}_{slug}.{ext}             # compute-gate producing scripts + data + plots
  inv{n}_gate_verdicts.txt             # compute verdict ledger (investigation track)
```

Compute-gate verdicts are emitted via `emit_verdict(session={n}, track="investigation", ...)` to `{{COMPUTATION_DIR}}/investigation-{n}/inv{n}_gate_verdicts.txt` (see `.claude/rules/gate-verdicts.md`). Only `compute` gates emit verdict lines; `review` / `workshop` gates close by artifact-existence.

## Per-wave plan file (fanout)

```markdown
# Investigation {n} Plan -- Wave {i}: {Theme}

**Date**: {date}
**Author**: {planner-type} (generated by /rclab-plan --investigation per-wave swarm)
**Owner agent**: {subagent_type -- domain owner for this wave's theme}
**Seed**: `{free-form source doc(s) this wave's items were translated from}`
**Plan source**: `sessions/investigation/investigation-{n}/investigation-{n}-seed.md`
**Working paper**: `sessions/investigation/investigation-{n}/investigation-{n}-w{i}-workingpaper.md`

## Wave {i} Summary

{One paragraph: what this wave resolves; which seed items it translates; the gate-type mix.}

## Wave {i} Gate-Type Manifest

{One row per gate. This is the manifest /rclab-coordinate reads to branch dispatch. A wave may be single-type or mixed.}

| Gate ID | gate_type | Scope |
|:--------|:----------|:------|
| INV{n}-W{i}-1 | compute | ... |
| INV{n}-W{i}-2 | workshop | ... |
| INV{n}-W{i}-3 | review | ... |

## Wave {i} Decision Point Prerequisites

{Which upstream verdicts / deliverables gate any item in this wave. compute prereqs reference
inv{n}_gate_verdicts.txt by gate ID; review/workshop prereqs reference the upstream deliverable.
If a prereq is unmet at dispatch, the gate honestly closes -- never as PASS.}

## W{i}-1. {Gate ID 1}  [gate_type: {type}]

{Full gate block. Set gate_type explicitly.
- compute: Agent / Model / Cost / full self-contained Prompt (method, inputs, pre-registered gate
  PASS/FAIL, output files) + verdict-line closure pinned to the investigation-track path.
- review: the review block (agents / sources / output paths / context); no numeric gate;
  output = one synthesis per agent (no verdict line).
- workshop: the workshop block (EXACTLY 2 agents / rounds / sources / output path /
  adjudication question / context); no numeric gate; output = the workshop md (no verdict line).}

## W{i}-2. {Gate ID 2}

{...one block per gate in this wave; types may be mixed...}

## Wave {i} -> Wave {i+1} Decision Point

{If Wave {i+1} consumes Wave {i} outputs: which gates, what verdict/deliverable patterns trigger
which downstream action. Document branching for each PASS/FAIL/INFO (compute) or
landed/not-landed (review/workshop) outcome.}
```

```markdown
## I. Investigation Objective

{1-2 paragraphs: what this investigation resolves; how it descends from the seed's findings.}

## II. Wave Structure

{ASCII dependency graph: which waves run in parallel, which depend on prior verdicts/deliverables.
Annotate each wave with its gate-type mix.}

## III. Wave {M}: {Wave Title}  [types: {compute/review/workshop mix}]

### W{M}-{L}: {Gate ID}  [gate_type: {type}]

{Full gate block, gate_type set explicitly (compute / review / workshop field sets as above).}

## IV. Constraint Gates Summary

| ID | gate_type | Condition | Fires If | Consequence |

## V. Decision Points

**After Wave {M}**: if {condition A} -> {action A}; if {condition B} -> {action B}.

## VI. Execution Notes

- Python (compute gates): {project's configured Python environment}
- Output: `{{COMPUTATION_DIR}}/investigation-{n}/` (inv{n}_*.* scripts, verdict file, data, plots)
- Script prefix: `inv{n}_`
- Verdict file: `{{COMPUTATION_DIR}}/investigation-{n}/inv{n}_gate_verdicts.txt` (emit via track="investigation")
```


## Plan-Authoring Disciplines

The plan author MUST satisfy these at plan-freeze. The first block is shared with the session pipeline; the second is investigation-specific.

### Shared with `plan-compute.md` (apply to compute gates)

| Concern | Authoritative source |
|:--------|:---------------------|
| Per-gate pre-registration completeness (compute) | `.claude/rules/gate-verdicts.md` "Pre-Registration Protocol" (+ the discipline pack's pre-registration rule, if any) |
| Verdict-line schema + canonical path | `.claude/rules/gate-verdicts.md` (use the investigation-track path) |
| Double-check / substitution chain for sign/direction/threshold claims | the discipline pack's compute-script rule, if the pack defines one |

### Investigation-specific

| Concern | Discipline |
|:--------|:-----------|
| `gate_type` set on every gate | One of compute/review/workshop; absent => compute (a session gate that wandered in). Mixed waves are normal. |
| review/workshop closure | Artifact-existence-with-content; NO verdict line; NOT pre-registration-vulnerable for lacking a numeric threshold. |
| workshop gate = exactly 2 agents | Per `/rclab-workshop` Phase-0 validation. A "workshop" with 1 or 3+ agents is mis-typed -> re-type as review. |
| Seed traceability | Every gate item traces to a specific seed finding. No invented items -- the seed is the scope, the way prior-session WP carry-forwards are the scope in session mode. |
| Index registration | `/rclab-plan --investigation` registers `investigation-{n}` in `sessions/investigation/index.md` at plan-freeze (topic + driver/seed + PLANNED status). `/rclab-investigate` housekeeps it on close. Both touch the index; neither invents rows. |
| Verdict track | compute gates pin the verdict source to `{{COMPUTATION_DIR}}/investigation-{n}/inv{n}_gate_verdicts.txt`, NEVER a `session-{N}` path. |

A compute gate block missing a required pre-registration field, or pinning a non-canonical verdict-file path, will not pass the validator suite. A review/workshop gate is validated by its `review:` / `workshop:` block + artifact-existence output instead.
